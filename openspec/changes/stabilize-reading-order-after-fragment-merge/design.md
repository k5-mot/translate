## Context

[proposal.md](proposal.md)のWhyと[原因調査](verification.md)を参照。現行の`_reading_order`は各要素の先頭provだけから幅中央値と段の左端候補を計算する。結合処理はprovを連結するが、結合元をchildren/collectionから除くため、次のsortでその座標が標本から落ちる。

## Goals / Non-Goals

**Goals:** 既存の座標・段組heuristicを保ち、結合前後で推定に使う標本を保存情報の追加なしに維持する。代表位置と統計用座標の責務を分ける。

**Non-Goals:** 新しい段組認識器、固定段数、LLM推定、独自状態/Cache、収束するまでsort/mergeを繰返す方式。文書モデル全体の複数ページ表現を再設計しない。

## Decisions

### 1. 統計用の標本は既存provの全有効座標から取得する

要素の所属ページとsort keyには従来の先頭provによる代表geometryを使用する。その要素の既存provから、代表ページと同じページの有効なgeometryを列挙し、幅の中央値と左端候補の双方へ使う。先頭だけへ戻したり、同じ座標だからという理由で標本を除重しない。結合前の各断片が持つ標本の多重集合を、結合後もprovから得るためである。

座標変換は既存`_geometry`、中央値は標準`statistics.median`、sortは既存keyとPythonの安定sortを使う。既存Module内の必要な小変更に限定し、汎用layout解析層や依存を増やさない。代表位置がない要素は従来どおり座標なしの安定順に置き、別ページや不正な出典で段組統計を補わない。

幅だけを補正する案は不十分。幅中央値が変わらない合成例でも、結合元の左端が消えることで段候補が変わることを確認した。全要素一律の固定幅・固定段間隔は文書依存の判定を別仕様へ変えるため不採用。元の要素数や順序の保存フラグは、既存provで足りるため不要。

### 2. 同一ページ結合の境界を代表位置でも確認する

連鎖結合の末尾位置は引き続き使うが、結合先と結合元の代表ページも一致することを変更前に確認する。末尾provだけ一致し代表ページが異なる候補は既存の曖昧候補の警告経路へ渡し、変更しない。本文だけでなく表結合にも同じ境界を適用する。これは別ページの要素を先頭ページへ移して標本を失うことを防ぐためであり、新しい跨ページ結合機能は作らない。

### 3. 一度のsort/mergeで同じ順序を維持する

同一ページの標本集合が保存されれば、段位置・許容幅は結合前後で同じになる。残る各要素の代表geometry、領域labelは不変なので、sort keyも不変となる。同位置の場合は既存の安定順を維持する。繰返しsortで見かけ上収束させたり、二回目以降をskipする状態は導入しない。

この説明だけを完了証拠にせず、実POSITIONを二回・三回適用し、documentと実NORMALIZE→LOADの順序を比較する。前Changeの内容/参照の保存Testも併せて実行する。

## Quality Attribute Design

| ID | 手段と検証 |
| --- | --- |
| Q-FUNC/Q-REL | 幅変化・左端消失の最小fixture、複数provとページ境界、表と本文の連鎖、複数回適用で順序・内容・参照を比較する |
| Q-COMP/Q-MNT | 既存座標変換/中央値/sort/Task/保存処理へ委譲。読み順/欄外/欠損座標とReview/registerを含む全回帰を行う |
| Q-SEC/Q-INT | reportは従来の参照列と固定理由を使い、本文・秘密の追加保存なしを差分とmarker Testで確認する |
| 性能効率 | 既存provを有限走査し、統計・sortは呼出内だけ。外部要求と新しい永続状態は0件 |

## Lifecycle, Migration and Operations

実装は既存POSITION Testに再現ケースを追加してから行う。保存済みsample3のMERGE Artifactは読取り専用で、一時領域で二回のPOSITIONとLOADを比較し、元hash不変を確認する。その補助検証と、新規推論OFF・逐次Translation→Microsoft Word PDF→Review・利用者目視を区別する。

## Risks / Trade-offs

- [Risk] 全provに別ページの座標が混入する → 代表ページ単位で限定し、代表ページを跨ぐ結合を未変更で保持する。
- [Risk] 先頭prov以外を持つ既存文書で初回の順序が変わる → 出典全体に基づく段推定としてfixtureと実PDFで妥当性を確認する。単なる再適用一致だけで元PDFの順序保持を証明しない。
- [Risk] 幅だけを維持し左端の変化を見逃す → 幅と左端の独立した再現fixtureを必須とする。
- [Risk] 安定性だけを理由に既知の誤順序を固定する → 元PDFとのReview・利用者目視を受入条件に残す。

## Migration Plan

保存形式の変更・migration・旧版切替は追加しない。新しい処理で検証し、既存Runを成功証拠として付け替えない。rollback時も利用者の入力/成果物は変更・削除しない。
