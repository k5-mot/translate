## Context

動機は[proposal.md](proposal.md)を参照する。[既存の診断](../restore-docx-tables-and-indexes/verification.md)で、同梱テンプレートと生成DOCXの仮表示が一致した。`create_docx`は指定参照DOCXをPandocへ渡し、`_normalize_docx`はヘッダー／フッターを中立化していない。

テンプレートは12個、既存生成DOCXは1個の`sectPr`を持つ。生成DOCXの先頭は空の`header2/footer2`、通常ページは`header1/footer4`を参照する。`footer4`にはSAVEDATEしかなく、別部品のPAGEを残すだけではページ番号を表示できない。

## Goals / Non-Goals

**Goals:** 同梱資産の必要な部品だけを修正し、文書構造・スタイル・参照整合性を保つ。テンプレートの全部品検査と、生成物の有効な参照先検査を区別する。

**Non-Goals:** 汎用の仮文言削除器、実行時テンプレート識別分岐、旧版切替、利用者の独自テンプレート修復、本文や既存成果物の書換えは追加しない。表・一覧・見出し採番の既存Changeを再実装しない。

## Decisions

1. **同梱資産を修正する。** 全ヘッダー部品を空の段落へ、通常／偶数ページ用フッターをPAGEだけの段落へ置換する。先頭ページ用の空部品と`titlePg`は維持する。リレーションを解決して用途を判断し、部品名の番号で用途を決めない。同一部品の共用がある場合は参照用途を壊さないよう分離する。未使用部品にも仮表示を残さない。
2. **ページ番号は動的PAGEとする。** 固定文字の「1」に置換しない。本文開始での採番リセットやローマ数字化は追加せず、既存のページ計数を維持する。最初のページを空にする点は現状維持の前提である。`STYLEREF`、`SAVEDATE`、付録用`A-`は不要。強制自動更新設定やdirtyフラグは追加しない。
3. **独自テンプレートは同じ変換経路で利用する。** 資産だけの修正により独自ヘッダー等を巻き込まない。既存の外部File参照拒否は維持する。「○○」等の本文文字列を検索削除する案は正当な入力を損なうため採用しない。
4. **既存Testへ回帰検証を追加する。** `tests/test_output_contract.py`でZIP/XMLの全部品、`sectPr`→relationships→有効部品の対応、実Pandoc生成物、独自テンプレートを検証する。Word実表示は別の手動相当検証として記録する。新しい製品moduleや依存は不要。
5. **仕様と資産説明の責務を分ける。** 表示契約は本ChangeのSpec、`template-style.md`には資産の具体的内容と出力時の扱いを記載する。「テンプレート本体は変更しません」は見出し採番の実行時処理を指すと明確化する。全110スタイルの一覧を再照合するが、スタイルそのものは変更しない。

承認経緯: ヘッダーなし／ページ番号のみ、独自テンプレート保持を前回提案し、利用者の「つづけて」を採用方向として受けた。用語の新設や不可逆なアーキテクチャ判断はなく、追加の用語集・ADRは不要。

## Quality Attribute Design

| 品質ID | 検証Evidence |
| --- | --- |
| Q-FUNC | 全部品で仮文言0、PAGE以外のfield0。生成物の有効通常フッターにPAGE、先頭は空 |
| Q-COMP | 独自の社名・PAGEを持つ参照DOCXで表示保持、入力hash不変。本文の仮文言類似文字列保持 |
| Q-INTERACTION | 複数ページのWord PDFで先頭と通常ページを目視確認し、ページ番号が実ページに対応 |
| Q-REL | 参照切れ0、実Pandoc成功、既存の失敗時完全版保持Test成功 |
| Q-SEC | 外部参照・dirty・自動更新要求を追加しない。Wordポップアップの回帰を確認 |
| Q-MAINT | 差分部品を列挙し、styles等の非対象部品が不変。追加依存・変換経路0 |

## Lifecycle, Migration and Operations

修正資産を新規生成時から供給する。既存DOCX/PDFはユーザの成果物として保持する。Microsoft WordによるPDF作成は運用上の操作であり、製品CLI/UIへ実装しない。実サービスによる新規sample3検証は、既存の受入Changeでreasoning OFF・完全逐次実行し、本Changeへ結果を参照する。単体のテンプレート検証成功を翻訳全体の受入成功とはしない。

## Risks / Trade-offs

- [未使用フッターだけを検査して誤合格] → 生成DOCXの有効参照を解決する否定Testを追加する。
- [Wordのキャッシュ表示をPAGEと誤認] → XMLのfield構造と複数ページPDFの実番号を両方確認する。
- [テンプレート保存時に全スタイルが変更される] → ZIP部品差分を比較し、対象外の変更を除く。
- [Word確認や外部サービス検証が実行できない] → 未検証をtasks/verificationに残し、archiveしない。

## Migration Plan

移行・互換実装は行わない。Gitで管理する資産変更としてレビュー可能にし、既存出力の一括再生成や削除を行わない。修正に問題があれば公開を止め、同梱資産を再修正する。旧版共存機能は設けない。
