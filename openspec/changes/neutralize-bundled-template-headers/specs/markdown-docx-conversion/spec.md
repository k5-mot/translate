## ADDED Requirements

### Requirement: 同梱テンプレートは中立なヘッダーとフッターを持つ
Systemは同梱テンプレートで新規生成するDOCXのヘッダーを空とし、先頭ページのフッターを空、それ以降のフッターを現在ページ番号だけにしなければならない（MUST）。原文にない組織名、文書名、機密表示、更新日、付録接頭辞をヘッダー／フッターに表示してはならない（MUST NOT）。本文中の同一文字列は削除してはならない（MUST NOT）。

#### Scenario: 同梱テンプレートから複数ページのDOCXを生成する
- **WHEN** 利用者が同梱テンプレートを使用して複数ページの文書を生成する
- **THEN** 全ページのヘッダーと先頭ページのフッターは空である
- **AND** 以降のページのフッターには現在ページ番号だけが表示される
- **AND** 本文にある組織名、日付などの文字列は保持される

### Requirement: 独自テンプレートを中立化しない
Systemは利用者指定の独自テンプレートに対し、同梱テンプレートの仮表示を除去する規則を適用してはならない（MUST NOT）。既存の安全性検査を満たすヘッダー／フッターの表示内容を保持し、指定されたテンプレートFile自体を書き換えてはならない（MUST NOT）。

#### Scenario: 独自テンプレートに利用者の社名がある
- **WHEN** 利用者が社名とページ番号を持つ安全な独自テンプレートを指定する
- **THEN** 生成DOCXはそのヘッダー／フッターの内容を保持する
- **AND** 元テンプレートFileの内容は変化しない

### Requirement: ヘッダーとフッターの実表示を検証する
Q-FUNC（機能適合性）として、同梱テンプレートの全ヘッダー／フッターと生成DOCXで有効な参照先の検査により、仮文言・日付・文書名参照を0件とし、通常ページのフッターが現在ページ番号だけであることを確認しなければならない（MUST）。Q-INTERACTIONとしてMicrosoft Wordで表示・PDF化した結果でも同じ契約を検証しなければならない（MUST）。Q-COMPとして独自テンプレート入力のhash不変と表示内容保持を回帰Testで確認しなければならない（MUST）。

#### Scenario: 未使用部品にだけページ番号が存在する
- **WHEN** DOCX内の未参照フッターにページ番号があるが、有効な通常ページ用フッターにはない
- **THEN** 検証は不合格となる

#### Scenario: Wordによる表示を確認する
- **WHEN** 検証者が同梱テンプレートの複数ページ生成DOCXをMicrosoft Wordで開いてPDF化する
- **THEN** 先頭ページの空表示と以降のページ番号のみの表示を確認する
- **AND** 自動更新確認の新たなポップアップや仮表示があれば検証を不合格とする
