## ADDED Requirements

### Requirement: 重複実行の拒否で実行所有者の保存情報を変更しない
Systemは、同じRunの実行権を他の呼出が保持している場合、新しい実行を拒否し、所有者のmetadata、失敗記録、log、checkpointおよび成果物を変更してはならない（MUST NOT）。拒否された呼出はWorkflowと外部Serviceを開始してはならず、既存の失敗記録を今回の拒否原因として報告してはならない（MUST NOT）。所有者は実行開始準備から成功または失敗の記録と後処理まで排他を保持しなければならない（MUST）。Q-RELおよびQ-SECとして、実排他を保持した拒否Testで保存内容の変更と外部処理呼出を0件とし、公開Errorには拒否原因を含め秘密・本文・内部pathを含めないことを検証しなければならない（MUST）。

#### Scenario: 実行中のRunへ再度実行を要求する
- **WHEN** CLIまたはStreamlitから、他の呼出が実行中の同じRunへ実行を要求する
- **THEN** Systemは今回の呼出だけを拒否し、所有者の保存情報と実行を変更しない

#### Scenario: 過去の失敗記録があるRunで拒否する
- **WHEN** 所有者が再開中で過去の失敗記録が残っているRunへ重複実行を要求する
- **THEN** Systemは過去の記録を変更せず、今回の排他拒否だけを安全に呼出元へ通知する

#### Scenario: 実行所有者が終了を記録する
- **WHEN** 所有者が処理の成功または失敗を記録し、実行後処理を行う
- **THEN** 終了記録と後処理が完了するまで別の呼出は実行権を取得できない

#### Scenario: 所有者の終了後に再開する
- **WHEN** 所有者が停止して実行権を解放した後、互換なRunのResumeを要求する
- **THEN** Systemは最新の保存情報を使用して通常のResumeを実行し、過去の重複拒否をRun失敗として扱わない
