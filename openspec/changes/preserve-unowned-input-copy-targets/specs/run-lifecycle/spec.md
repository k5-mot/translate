## ADDED Requirements

### Requirement: 入力コピー失敗時に既存データを保全する
Systemは、入力コピー先の新規作成に成功する前に処理が失敗した場合、そのコピー先を後始末として削除または上書きしてはならない（MUST NOT）。新規作成後にコピー、同期、hash計算またはmetadata保存が失敗した場合は、今回作成した不完全なコピーを除去し、入力保存を失敗として通知しなければならない（MUST）。OSによって後始末が拒否されても元の保存失敗を成功へ変えず、元の失敗を通知し、部分コピーを有効な入力や成功済みRunとして公開してはならない（MUST NOT）。Q-REL/Q-SECとして、作成前と作成後の障害注入Testで既存入力・既存Run・外部成果物の変更を0件にしなければならない（MUST）。

#### Scenario: コピー先が既に存在する
- **WHEN** 入力コピーの開始時にコピー先が既に存在し、新規作成が拒否される
- **THEN** Systemは入力保存を失敗とし、既存先の内容を保持して削除・上書きしない

#### Scenario: コピー元を開けない
- **WHEN** コピー元の読取り開始に失敗し、コピー先はまだ作成していない
- **THEN** Systemは読取り失敗を通知し、指定されたコピー先の削除を試みない

#### Scenario: コピー先作成後に失敗する
- **WHEN** 新規コピー先の作成後にコピー、同期、hash計算またはmetadata保存が失敗し、OS上は後始末が可能である
- **THEN** SystemはFileを閉じて不完全なコピーを除去し、元入力と他の既存データを保持して、元の保存失敗を通知する

#### Scenario: 不完全コピーの後始末も失敗する
- **WHEN** 入力保存に失敗し、OSが不完全なコピーの削除も拒否する
- **THEN** Systemは元の保存失敗を通知し、残った部分コピーを有効な入力として扱わず、処理を成功扱いしない

#### Scenario: 既存の実行保存先と衝突する
- **WHEN** 新規実行の保存先が既存Runの保存先と衝突して排他的作成に失敗する
- **THEN** Systemは既存Runとその入力・成果物・metadataを変更せず、新規作成を失敗とする
